# Drive Folder Inventory

A read-only list of the files in Drive folders the user approves, written into a vault note so the vault, search and the agent index can see what lives in Drive without syncing it. Default off (`cloud-inventory`, external-account boundary, stage Capture); byte-identical when off.

## What the user does

One guided setup (`Set up Drive folder inventory`, or Settings → Integrations): pick a vault folder, paste its Drive folder link, copy the generated script into a new Apps Script project, deploy it, paste the web-app link back, press Test connection, Finish. Everything else is automatic. Refresh is `Refresh Drive inventories`; `Check Drive inventories` reports what changed without writing.

## Moving parts

| Piece | File | Notes |
|---|---|---|
| Script template | `src/services/cloudInventory/scriptTemplate.ts` | Pure `buildInventoryScript({ secret, rootFolderIds })`. Config is JSON-escaped into one `CONFIG` object, so a hostile value cannot leave its string. Read-only: no create/update/remove/trash/trigger calls (pinned by a test). |
| Apps Script client | `src/services/appsScriptClient.ts` | Shared with later features. `validateScriptUrl` accepts only `https://script.google.com/macros/s/<id>/exec`. The secret travels in the POST body, never the URL. Retries (max 5, growing delay) only `script-drive-error` and `script-network`; auth, not-approved and sign-in pages never retry. |
| Drive walk | `src/services/cloudInventory/driveListClient.ts` | Pooled breadth-first walk, concurrency 2, visited set, repeated page-token abort. Hitting the folder/file/time limit gives `truncated`; any request failure gives `failed` with no files. |
| Hub note block | `src/services/cloudInventory/inventoryBlock.ts` | Start/end markers keyed by pair and Drive folder. `findOwnedBlock` reports `marker-conflict` on duplicates, a missing half, wrong order or nesting and the caller writes nothing. All Drive-derived text is escaped, so a file name cannot forge a marker or break the table. |
| Service | `src/services/cloudInventory/cloudInventoryService.ts` | `testConnection`, `refreshPair`, `checkPair`, `hubNotePath`. Writes go through `applyNoteEdit`; protected locations are refused. |
| Link parser | `src/services/cloudInventory/driveLinkParser.ts` | Accepts a folder id or a `drive.google.com` folder link only. |

## Invariants

- **Authorisation lives in the script, not the client.** Every folder request must be (or descend from) an approved root; the plugin additionally hashes the approved roots (`rootsHashOf`) and compares it with the script's `ping` answer, so adding a folder after deploy reads as *out of date* until the script is replaced.
- **The secret is generated by the plugin and stored in SecretStorage** (`ai-organiser-cloud-inventory-secret`), never in settings. It appears once in the generated script text and is redacted from every log and notice (`redact`).
- **A listing is `complete`, `truncated` or `failed`.** Only `complete` and `truncated` write; `truncated` is labelled in the block. Nothing is deleted from the note because a listing was short.
- **A refresh with no change is a byte-identical no-op**, and keeps the previous listed time. A hand-edited row inside the block is restored on the next refresh; the user's own text outside the markers is never touched.
- **Existing note without a block**: the user is asked before a block is appended; declining leaves the note byte-identical.
- **Hub note location**: beside the folder by default (`<folder> — Drive.md`), inside it on request; a protected folder always gets the note beside it, and a pair whose final location is protected is refused.
- **Setup health** (`evaluateSetup('cloud-inventory')`): not set up until Finish; needs attention while the connection is untested, failed, or stale for the current script URL and folders (`inventoryConfigKey`).

## Settings

`cloudInventoryScriptUrl`, `cloudInventoryPairs` (`id`, `vaultFolder`, `driveFolderId`, `placement`, optional `label`), `cloudInventoryMaxFolders` (300), `cloudInventoryMaxFiles` (3000), `cloudInventoryDeadlineMinutes` (clamped), `cloudInventoryLastTest`. `migrateOldSettings` drops invalid or duplicate pairs and clamps the limits.

## Tests

`appsScriptClient`, `cloudInventoryScript`, `driveListClient`, `inventoryBlock`, `cloudInventorySetup`, `cloudInventoryOffPath`.

## Reuse

The F5 offload (planned) reuses `appsScriptClient.ts` and the per-pair mapping to a local Drive-for-desktop folder; it adds no second client.

## Drive large-file offload (F5)

Moves a large vault file into the user's own Google Drive for desktop folder and turns every reference to it into a Drive link. Default off (`cloud-offload`, stage Maintain, requires `cloud-inventory`), desktop only, never registered on mobile. Entry points: **Offload to Drive** on a large, referenced file in the Find embeds results, and **Resume offload** in the command palette (plus a prompt on load when one was left unfinished).

The Apps Script stays read-only: the plugin copies into the Drive for desktop folder and Drive uploads it. Each pair gets an optional `localMountFolder` (settings, shown when the feature is on) with a **Check folder** button that writes nothing.

| Piece | File | Notes |
|---|---|---|
| Typed occurrences | `services/offload/referenceOccurrences.ts` | Pure. Wikilinks, embeds, Markdown links and images, canvas `file` nodes, each with an exact span and a defined conversion. HTML tags, reference definitions, properties and canvas text cards are `unsupported`, which makes the file ineligible. Fenced and inline code are never rewritten. |
| Plans | `services/offload/offloadPlan.ts` | Pure. The copy plan (approved at "Start offload") and the rewrite plan (built once the Drive id is known and approved in "Final review"), plus the remote match rule (name, size and `sha256Checksum` must all agree; no checksum = no match). |
| Local copy | `services/offload/localMount.ts`, `fingerprint.ts` | Streamed with an incremental sha256, never buffered whole. `realpath` containment of the mount root and target, reserved names refused, exclusive open (`wx`) so nothing is overwritten: an identical file is reused, a different one gets `name-<8 hex>.ext`. |
| Journal | `services/offload/offloadJournal.ts` | One signed record per operation in the plugin folder, temp-and-rename like the agent index. Steps: `planned → copied → remote-captured → rewrite-approved → rewriting → verified → trash-pending → trashed → done` (or `aborted` / `failed`). Abort only before the first rewrite. |
| Orchestrator | `services/offload/offloadService.ts` | Recovery from observable postconditions: a referrer whose text already hashes to the planned after-text is done; one that hashes to the baseline is rewritten; anything else is a conflict that stops that referrer. A missing source after `trash-pending` completes the step; before it, the operation fails. |
| Commit barrier | `services/offload/commitBarrier.ts` | Last gate before the trash: every referrer done, Drive file still matches a fresh listing, source still matches its fingerprint, protection holds, a fresh authoritative reference scan finds nothing, and no vault event invalidated the check (it re-runs up to three times). |
| Canvas | `services/canvas/canvasWritePort.ts` | The only code that edits an existing canvas: a `file` node becomes a `link` node keeping id, position, size and colour; baseline-checked inside `vault.process`; protected canvases refused. |
| Runtime | `services/offload/offloadRuntime.ts` | Connects the service to the vault: note edits through `applyNoteEdit` (full-replace with the exact baseline, no review modal because the Final review step is the gate), trash through `fileManager.trashFile`, listing through the shared `appsScriptClient`. |

Invariants: a note edited after the plan is skipped and reported, never overwritten; the original file is trashed only after the barrier passes and only into the Obsidian trash; a protected source or referrer blocks the whole operation. Tests: `offloadReferenceOccurrences`, `offloadPlan`, `offloadLocalMount`, `offloadCommitBarrier`, `offloadJournal`, `offloadService`, `canvasWritePort`, `cloudOffloadOffPath`, `protectedWriteSites`.
